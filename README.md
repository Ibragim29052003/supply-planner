# Планировщик поставок · C# / .NET 10

Самостоятельное локальное приложение для планирования пополнения товаров по
складам. Окно Avalonia и консольная программа используют одно расчётное ядро.
ChatBot WB, браузер, серверы и токены маркетплейса не требуются.

Полный сценарий запуска, импорта, проверки Excel и защиты: [пошаговая инструкция](docs/QUICKSTART.md).
Формат данных: [DATA_FORMAT.md](docs/DATA_FORMAT.md).
Установка, все JSON и реальная связь с сервисом: [SELLERSTATUS_AND_SETUP.md](docs/SELLERSTATUS_AND_SETUP.md).

## Запуск

Нужен .NET SDK 10. Откройте эту папку в Visual Studio Code.
На первом запуске нужен интернет для восстановления пакетов NuGet; затем
учебные примеры и расчёты работают без сети.

```bash
./run.sh
```

Откроется отдельное окно. При первом запуске встроен пример из пяти позиций
на двух складах. Начало модели фиксировано на **13.10.2026**.

Windows/PowerShell или любой терминал с .NET:

```text
dotnet run --project src/SupplyPlanner.Desktop
dotnet run --project src/SupplyPlanner.Desktop -- --open examples/01-base.json
```

Остановка: закрыть окно. Приложение сохраняет последний применённый сценарий
для восстановления при следующем запуске. Неприменённые правки требуют решения
при закрытии. Чтобы перенести состояние на другой компьютер, используйте
«Сохранить…», затем «Открыть…», а не копирование bin/obj.

## Интерфейс

- **План:** поиск, фильтры, сортировка, итоги по складам, график и дневной расчёт.
- **Исходные данные:** двойной щелчок по остатку или истории для редактирования.
  История вводится по датам через `;`. `?` означает неполный день, пустой остаток
  означает неизвестное значение. Нажмите «Рассчитать», чтобы применить правки.
- **Поступления:** выбрать товар со складом, указать дату `дд.ММ.гггг` и количество.
  Добавление/удаление пересчитывает план и создаёт события C#.
- **Журнал:** результаты подписок на DeliveryChanged, ShortageDetected, PlanCalculated.
- **Excel:** выгрузка текущего списка в три листа; это результат, а не Excel-калькулятор.
- **Сохранить:** JSON-проект с исходными данными, журналом, фильтрами и выбранной
  позицией. При открытии результат пересчитывается; неподдерживаемая версия или
  ошибочный файл не заменяет текущие данные. Старые файлы сценариев поддерживаются.

Cmd/Ctrl+O — открыть; Cmd/Ctrl+S — сохранить; Cmd/Ctrl+Enter — рассчитать;
Cmd/Ctrl+F — поиск; F1 (на Mac иногда Fn+F1) — справка. В графике: ← →, Home, End.
Тема и размер окна сохраняются отдельно в пользовательской папке `SupplyPlanner`.
Для изолированной демонстрации можно задать `SUPPLY_PLANNER_DATA=/путь/к/папке`.

## Проверяемые примеры

| Позиция | Базовая рекомендация |
|---|---:|
| Футболка WB-1001 · Коледино | 300 |
| Футболка WB-1001 · Казань | 132 |
| Худи WB-1002 · Коледино | 260 |
| Шапка WB-1005 · Казань | 0 |
| Сумка WB-1007 · Коледино | Нет оценки |

Сумма **692**; Казань **132**, Коледино **560**. Неизвестная потребность не входит
в сумму. Измените остаток футболки Коледино 100→150 и рассчитайте: 300→250;
Казань останется 132. Упаковка 16 округляет исходные 300 до 304. Взвешенный метод
изменяет прогноз худи 9→10 и новую поставку 260→300.

## Командная строка

```bash
./cli.sh --help
./cli.sh calculate --input examples/01-base.json
./cli.sh calculate --input examples/01-base.json --warehouse Казань --excel output/kazan.xlsx --state output/project.supply.json
./cli.sh calculate --input output/project.supply.json --output output/plan.json
./cli.sh demo --output output/scenario.json
```

CLI по умолчанию не перезаписывает существующие файлы; разрешение — `--force`.
Входной файл нельзя использовать как выходной. Код завершения 0 — успех, 2 — ошибка.
JSON отчёта отличается от JSON проекта: отчёт — результат выбранного списка,
проект — все входные позиции и состояние работы. Jupyter для запуска не нужен.

## Структура

```text
src/SupplyPlanner.Core             модели, прогнозы, симуляция, события, запросы
src/SupplyPlanner.Infrastructure   JSON-проекты, настройки, Excel, workflow
src/SupplyPlanner.Desktop          Avalonia, MVVM, диалоги, график на C#
src/SupplyPlanner.Cli              параметры и команды без графического интерфейса
tests/                            ядро, файлы, CLI, привязки, layout и клавиатура окна
examples/                         фиксированные сценарии защиты
docs/                             требования, защита, архитектура, перенос
```

Ядро не зависит от Avalonia, HTTP, SQLite или Excel. Оба клиента подключают его
через ProjectReference. В Infrastructure также сохранён проверенный SQLite-адаптер
старой версии; Desktop/CLI используют файловые проекты и не требуют базы.

## Проверки

```bash
./test.sh
```

Для сохранения изображений отрисовки окна (headless Skia):
`PLANNER_QA_OUTPUT="$PWD/output/qa" ./test.sh`.
Это автоматическая проверка окна; нативные системные файловые диалоги стоит
также пройти вручную перед защитой. Сценарий — `docs/DEFENSE.md`.

## Ограничения

Прогноз основан на истории, не гарантирует продажи. В модели приход утром,
расход вечером; потерянный спрос не переносится в долг. Поздняя поставка не
покрывает ранний дефицит. Срок доставки и упаковка общие для сценария.
Приложение не распределяет суммарный спрос по складам и не создаёт поставки WB.
Поддерживаются до 100 позиций и 500 поступлений, история до 60 дней, горизонт до 270 дней.

## Репозиторий и готовая сборка

Личный репозиторий: https://github.com/Ibragim29052003/supply-planner (публичный).
Преподаватель может открыть код без приглашения в репозиторий.
История коммитов отражает перенос рабочей версии и последующие реальные исправления.

Сборка для Mac с Apple Silicon: [релиз v1.0.1](https://github.com/Ibragim29052003/supply-planner/releases/tag/v1.0.1). Это .app со своим
.NET runtime, а не веб-сайт. Её упаковку можно воспроизвести на Mac:

```bash
./scripts/publish-macos.sh osx-arm64
```

Результат — ZIP и SHA-256 в output/release/osx-arm64/. В ZIP только приложение,
вымышленные примеры и инструкция. Это учебная ad-hoc подпись, без Apple notarization;
на другом Mac возможен запрос разрешения Gatekeeper. Для разработки и защиты
рекомендуется также иметь исходники и SDK10. Сборка для Intel: osx-x64 (локально
проверена архитектура arm64). Сервер SellerStatus не используется.

GitHub Actions собирает и запускает тесты Release на macOS, Windows и Linux.
Результаты конкретного запуска — во вкладке Actions. Полный локальный протокол
и ограничения проверок — [VERIFICATION.md](docs/VERIFICATION.md).
